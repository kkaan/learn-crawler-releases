LEARN data transfer pipeline

learn_upload

Desktop wizard that transfers Elekta XVI CBCT patient data from GenesisCare exports to the USYD RDS/research/PRJ-LEARN structure. Covers folder sorting, DICOM anonymisation, PII verification, and CBCT shift reporting. Replaces the manual anonymisation and sorting workflow.

learn_upload.exe
Single-file executable, published on the repository releases page. Download and double-click; nothing to install.
Built by GitHub Actions on windows-latest · Python 3.12 · PyInstaller · pydicom, PyQt6, numpy bundled

Before you run it
Work from a local drive

XVI exports contain thousands of small .his projection files. Reading them over a network share is much slower than working from local disk.

  1. Copy the patient_XXXXXXXX/ folder from the network to a local drive.
  2. Run learn_upload.exe.
  3. Point the source path at your local copy.
  4. Set the output path to another local directory, e.g. E:\LEARN_OUTPUT.
  5. When processing finishes, copy the output to the RDS research drive.

Wizard steps

STEP 1
Configuration
Paths, anonymised ID (PATxx), site name, PII search strings, dry-run option.
STEP 2
Data preview
Discovers XVI sessions, shows scan datetime, treatment ID, kV/mA, RPS presence, and fraction assignment.
STEP 3
Folder sort
Copies files into the LEARN directory structure by fraction and file type.
STEP 4
Anonymise
DICOM, XML, and INI anonymisation with per-file progress. Replaces the MIM workflow.
STEP 5
PII verification
Scans output for residual patient data. PASS or FAIL, with a findings table (file, location, matched string).
STEP 6
CBCT shift report
Writes cbct_shift_report.md to Patient Files/PATxx/ with per-fraction shifts in patient coordinates.

Inputs the tool expects

Required
XVI patient export
patient_XXXXXXXX/ containing the images subdirectory (IMAGES/ or XVI Export/, configurable). One img_<UID>/ per acquisition session with _Frames.xml, .his projections, and Reconstruction/ holding .INI, .SCAN, .SCAN.MACHINEORIENTATION, and .RPS.dcm.
Optional
TPS export
Whole tree is scanned and files are classified by DICOM Modality, not folder name: CT to CT/, RTPLAN to Plan/, RTSTRUCT to Structure Set/, RTDOSE to Dose/. Other modalities (e.g. RTIMAGE) are ignored. Missing categories are non-blocking warnings.
Optional
Trajectory logs and centroid file
FX01/, FX02/ ... subdirectories with MarkerLocations*.txt. Centroid file is a single .txt, e.g. Centroid_12345678_BeamID_1.1_1.2.txt; the MRN in the filename is replaced with the anon ID on copy.

Fraction assignment

FXnn labels are ground truth, not derived from dates.

PRIME patients
Trajectory FXnn/ folder names set by the RT or physicist are the fraction number. Every XVI session a trajectory log references is assigned by img_<UID>; dated referenced sessions anchor the fraction date, and only unreferenced setup CBCTs attach by that date. A same-day KIM restart (FX13 + FX13-1) is one fraction; its setup CBCTs go to base FX13.
Non-PRIME patients
No trajectory folders: Data Preview lists each distinct CBCT date and you enter the fraction number for each. Look these up in the Mosaiq patient schedule or image browser. One fraction = one day.

Sessions that cannot be placed unambiguously are flagged in Data Preview rather than silently mis-sorted.

Running from source

Requires Python 3.10+ and uv. uv creates a project-local .venv/, installs the learn_upload package with its dependencies, and pins versions in uv.lock. uv run syncs the environment before executing, so there is no venv to activate.

git clone https://github.com/kkaan/learn-crawler-releases.git
cd learn-crawler-releases

uv sync --extra gui --extra dev        # environment + GUI + dev tooling
uv run python -m learn_upload          # launch the GUI
uv run python -m pytest tests/ -v      # run tests
uv run ruff check learn_upload/ tests/ scripts/

Plain pip alternative: python -m venv .venv && .venv\Scripts\activate, then pip install -e ".[gui,dev]" and python -m learn_upload. Always use python -m pip so packages land in the interpreter that runs the code.
